Stock module

ERPNext Stock on its own

Every quantity lives in the Stock Ledger. A Stock Entry is the document that adds to it or takes from it. The Bin is the running total per item and warehouse; the Batch holds the same per lot.

Stock in: key facts

  • Stock Entry type Material Receipt adds to a warehouse with no supplier. Purchases use Purchase Receipt (same ledger).
  • Items with expiry need a Batch with an expiry date before they can be received.
  • The batch quantity and the Bin always equal the sum of the ledger.

Reorder

  • Each Item can have a reorder level per warehouse.
  • With “Raise Material Request when stock reaches re-order level” on, a daily job raises a request when the Bin falls to that level.
  • A Material Request never changes stock by itself.
Stock module

Stock out in ERPNext Stock

Stock leaves through a Stock Entry of type Material Issue. Batches are chosen by ERPNext, earliest expiry first, and expired lots are never used.

Settings that make this work

  • Stock Settings › Pick Serial / Batch Based On = Expiry.
  • Stock Settings › Use Serial / Batch fields = on (batch chosen on the row).
  • Item › Has Batch No = yes, Has Expiry Date = yes.

What a user sees

  • Material Issue with a source warehouse and the quantity.
  • On submit: ledger rows per batch, the batches shown in the bundle.
  • Too little valid stock: a clear error, nothing is posted.

Connection 1

Medication and Item

A Medication is the clinical product; an Item is the stock product. Health creates the Item from the Medication's linked-items table.

Findings (tested)

  • The Item is created as a stock item and a sales item, disabled when the row is not billable.
  • A Medication with no price list set needs the default selling price list, or it cannot be saved.
  • The batch, expiry and reorder settings of an Item are not touched by Health.

What to do about it

  • Give the Item its batch, expiry and reorder settings in the Stock module (Item defaults can do this for every new Item).
  • Enable the Item when the medicine is ready to use.
  • Keep one Item per Medication: the Medication refuses an Item already linked elsewhere.

Connection 4

Procedure to Stock Entry

This is the heart of the integration. A procedure lists the Items it uses. When it is completed, ERPNext issues them from the procedure's warehouse.

Rules (tested)

  • Warehouse: the one chosen on the procedure. It is filled from the Healthcare Service Unit's warehouse when a service unit is picked; otherwise the nurse chooses it (Stock Settings has no default warehouse in version 16).
  • Quantity is the procedure's own, not the template's: it can be changed per patient.
  • Start checks the total quantity in the warehouse; if short it offers a Material Receipt for the shortage.

Remember

  • Standard cancel does not return stock (next pages).
  • A procedure with Consume Stock = no never touches stock.
  • The Stock Entry has no patient on it for procedures.

Connection 5

Cancelling a procedure

A procedure recorded for the wrong patient has to be undone. The standard Cancel does only half the job.

Tested

  • Cancelling a completed procedure (as Physician): the procedure becomes docstatus 2; its Stock Entry stays submitted; the warehouse quantity does not change.
  • Nursing User cannot cancel procedures at all (only Physician can).

Decision

  • Either cancel the Stock Entry and the procedure together, in that order, every time.
  • Or add a link from the procedure to its Stock Entry, so that one action cancels both.

Permissions in the modules

Tested findings

  • A Nursing User alone cannot complete a procedure that uses stock: creating the Stock Entry is refused. Adding the role Stock User fixes it; nothing else is needed.
  • A Nursing User can create, submit and start a procedure, and read items and patients.
  • A Stock User can receive stock and raise requests but cannot read patients or procedures.
  • Only Physician can cancel a procedure.

A workable role set

  • Pharmacist: Stock User + Item Manager (create medicines and batches).
  • Nurse: Nursing User + Stock User (records and completes procedures).
  • Doctor: Physician + Stock User if they complete procedures.
  • Administrator: Healthcare Administrator (Medications, templates) + Stock Manager.
  • Site owner: System Manager.

Decisions

Gaps in the standard flow

These are properties of the standard modules, found by testing. Each one needs a decision, or a small addition.

Gap in the standard modulesConsequenceProposed answer
The procedure does not keep its Stock Entry numberNo way to see which stock a procedure used, or to cancel the right entryAdd a link field on the Stock Entry to the Clinical Procedure, filled when completing
Standard Cancel does not return stockA mistake leaves the medicines counted as usedCancel the Stock Entry with the procedure, in that order, and keep a reason
Items from Medication are disabled and not batch / expiry itemsMedicines cannot be used until fixed by handItem defaults for batch and expiry; enable the Item after creating the Medication
Start counts expired stockA procedure can start with no valid stock and fail at CompleteAccept: the refusal at Complete protects stock; show valid stock to the nurse
A Stock Entry has no reason or recipient“Why did stock leave?” is not recordedAdd two fields on the Stock Entry: reason and recipient
Nursing User cannot complete a stock-consuming procedure aloneNurses are blocked at the last stepGive nurses Stock User as well
Nurses cannot cancel; only PhysicianA wrong entry needs a doctorDecide who may cancel; add the role or a Healthcare Administrator step
Prescriptions never move stockDispensing a prescription is not a stock movementDispense through a procedure, or bill with a Sales Invoice that updates stock
How we answer them. A link field, a reason field and a recipient field are added to the Stock Entry; Item defaults and Stock Settings are configured; the roles above are used. Everything else is standard.
